personalitylinmult.onnx¶

The ONNX Runtime-backed counterpart to PersonalityModel.

A separate class, not a backend= flag on PersonalityModel: the two back ends have genuinely different runtimes (torch/lightning vs. onnxruntime) and this keeps a plain pip install personalitylinmult free of onnxruntime for callers who only want the PyTorch-native path (e.g. loading the trained weights as an nn.Module inside another PyTorch project). Install the onnx extra to use this class:

pip install personalitylinmult[onnx]

Both single-feature (LinT) and multi-feature (LinMulT, e.g. the AVT champion) checkpoints have an ONNX export path – see personalitylinmult.inference.onnx_export for how each is traced. predict() handles any number of features transparently, reading feature_names from the .onnx.json sidecar (always plural, regardless of family – a LinT sidecar simply has length-1 lists). Model ids for this class carry a .onnx suffix by HF Hub filename convention (see _onnx_filenames()), the same repo as the .ckpt files PersonalityModel downloads.

Two full raw-media pipelines are offered, matched to the champion they serve:

  • predict_from_audio() – audio only (wavlm-only champions): raw audio/video in, Big Five out, on ONNX Runtime alone, no torch/transformers/exordium at inference time. WavLM’s own ONNX export (WAVLM_ONNX_FILENAME) downloads lazily.

  • predict_from_media() – the full multimodal (AVT) champion: every learned feature extractor (WavLM, emotion2vec, DINOv2, EmotiEffNet, FaRL, mmBERT, XLM-RoBERTa) and the trained head itself run on ONNX Runtime, with two narrowly-scoped, explicitly-documented exceptions that stay torch/exordium-based: face detection/tracking (EmotiEffNet/FaRL need a face crop, not a raw frame – exordium’s existing offline-pipeline detector/tracker, reused for a single already-complete video file, not a live/streaming input) and Whisper ASR (an encoder-decoder model with no ONNX export in this project, used only when transcript=None). Both are dependencies of this method specifically, not of the class or of predict/predict_from_audio – a caller who never calls predict_from_media never needs torch/exordium installed.

personalitylinmult.onnx.EXTRACTOR_ONNX_FILENAMES: dict[str, str]¶

Shared ONNX graph filename per AVT feature, matching the Makefile’s push-<name>-onnx targets exactly – one file per extractor, reused across every champion that consumes that feature, not tied to one champion id (unlike the trained-model graph, which is).

predict_from_audio(audio_path: str, revision: str | None = None) → dict[str, float][source]¶

Predict Big Five scores directly from an audio/video file.

The full pipeline (decode -> WavLM -> LinT -> scores) on ONNX Runtime alone – no torch, transformers, or exordium needed. ffmpeg is still required as an external binary for decoding (a subprocess call, not a Python dependency).

The shared WavLM ONNX graph (WAVLM_ONNX_FILENAME) downloads on first use and is cached on this instance for later calls.

Parameters:

  • audio_path (str) – An audio or video file.

  • revision (str | None) – HF Hub revision for the WavLM graph download; None uses the default branch. Ignored on subsequent calls once the WavLM session is cached.

Returns:

{trait: score}, in the model’s trait order.

Return type:

dict[str, float]

Raises:

ValueError – If this model’s only feature is not "wavlm" – the only feature this method currently knows how to extract from raw audio. A multi-feature (AVT) champion needs predict_from_media instead (in progress).

predict_from_media(video_path: str, transcript: str | None = None, revision: str | None = None) → dict[str, float][source]¶

Predict Big Five scores from a video file, for the full AVT champion.

Runs every extractor this champion needs (feature_names, expected to be AVT_FEATURE_NAMES) on ONNX Runtime, except for two narrowly-scoped, explicitly-documented exceptions that stay torch/exordium-based – see this method’s own steps below and the module docstring’s “Dependencies” note:

  • Face detection/tracking (for emotieffnet/farl, which need a face crop, not a full frame): exordium’s YoloFace11Detector + FaceClusterTracker + AdaFaceWrapper stack, the same one this project’s own offline dataset-build (personalitylinmult/preprocess/fi/create_vdets.py, create_tracks.py) already uses per-clip – this is a batch call over one already-complete video file, not a live/streaming use case, so the existing offline-oriented API is exactly the right fit, not a mismatch to work around.

  • ASR (when transcript is None): exordium’s WhisperWrapper, lazily loaded, since Whisper’s encoder-decoder architecture with beam-search generate() has no ONNX export in this project (see onnx_export.py’s module docstring).

The video is only decoded/detected/tracked once and every extractor reuses that single pass – not once per feature.

Parameters:

  • video_path (str) – A video file (audio + visual features are both extracted from it).

  • transcript (str | None) –

    Controls how the two text features (xlm_roberta_gt, mmbert_gt) are resolved:

    • A non-empty string – used directly, no ASR.

    • None (default) – run Whisper ASR on the video’s audio track to obtain a transcript.

    • "" (empty string) – skip text entirely: both text features get a zero placeholder tensor with an all-False mask, verified NaN-safe and content-independent for this champion’s architecture (see predict()’s docstring).

  • revision (str | None) – HF Hub revision for every extractor graph download; None uses the default branch. Ignored for already-cached sessions.

Returns:

{trait: score}, in the model’s trait order.

Return type:

dict[str, float]

Raises:

ValueError – If this model’s features are not exactly AVT_FEATURE_NAMES (in any order) – this method is specific to the full multimodal champion, not the audio-only one (use predict_from_audio() there instead).
